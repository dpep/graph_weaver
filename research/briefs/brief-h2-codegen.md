You are the staff engineer who owns generation and `ResultStruct`. The standard from CLAUDE.md: no spooky action at a distance — generated output is a function of the schema, the query and the gem, never of what else is in the Gemfile or the require order.

- **A3**: `STRUCT_METHODS` is derived from `T::Struct.instance_methods` at load time, so (a) whether `asJson` is refused depends on whether ActiveSupport loaded first — and when it slips through the prop shadows `as_json`, so `render json: result` serializes the field; (b) `deconstruct` isn't reserved while `deconstruct_keys` is, and a prop named `deconstruct` makes array pattern matching destructure the field; (c) private `Kernel` methods are missing, so a prop named `raise` makes `Hints#method_missing`'s bare `raise` call the prop reader (`ArgumentError: wrong number of arguments`). Fix: union the derived set with an explicit frozen list the gem owns — `deconstruct`, `to_a`/`to_ary`/`to_hash`/`to_str`/`to_int`/`to_proc`, `to_json`, `as_json`, `to_param`, `to_query`, `try`, `presence`, `each`, and `Kernel.private_instance_methods(false)` — so the refusal set is a property of the gem. `ALIAS_RESERVED` in `codegen/aliases.rb` reads the same set. Specs: each of the three probes (`hunt2-rs-envdep2.rb`, `hunt2-rs-names.rb`, `hunt2-rs-raise.rb`) as a spec; and "byte-identical for the same inputs" must now hold with ActiveSupport loaded before or after. Regenerate fixtures; note in `docs/upgrading.md` (it already records `deconstruct_keys` being added reactively — one sentence for the list becoming explicit) and CHANGELOG (Regenerate if any fixture changed).
- **A4**: `ResultStruct#==` compares props with `Hash#eql?`, so a registered scalar class that defines `==` but inherits `Object#eql?`/`hash` — the docs' own `Money` example — makes two results parsed from the same bytes unequal, and the hash-key promise fails. Decide: warn at `register_scalar` when the class defines `==` but not `eql?`, and document in `docs/scalars.md`; or compare with `==` and hash on `to_s`; pick the one that keeps `==`/`eql?`/`hash` consistent and say why. Spec with a class shaped like the docs' Money.
- **A5**: `to_h` returns the live object for a scalar (a mutable `Hash` from a `JSON` scalar, a `String`), so mutating what `to_h` returned mutates the const struct and flips `==`. Freeze scalar values at cast time in the generated `from_h`, or dup non-struct `Hash`/`String`/`Array` in `unwrap_value` — pick the one with one rule; the freeze is closer to "a result is a value".
- **A6**: YAML round-trip returns a duplicate `T::Enum` instance, so `pet.species == Species::Dog` is false after `YAML.safe_load` (Rails' yaml cache coder). Emit `encode_with`/`init_with` on generated enum types so YAML rehydrates to the canonical instance, or document "Marshal-safe, not YAML-safe". Prefer the emit if it's contained; spec the round-trip.
- **D5**: `docs/generated_modules.md` ~189: add the counter-example — `JSON.generate(result.to_h)` writes `BigDecimal` as `"0.125e2"` and a `Time` without ISO 8601 shape; `to_h` is the Ruby view, `Response#to_h` is the wire.
