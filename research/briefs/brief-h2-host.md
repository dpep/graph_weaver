- **A9**: `Internal::Util.generated_dirs` decides an output is "already covered" with `File.fnmatch?` and no `FNM_PATHNAME`, where `*` crosses `/`; Zeitwerk and `load_generated!` use `Dir.glob`, where it doesn't. So `app/graphql/a/b/generated` is dropped as covered and is then neither ignored nor loaded — production boot dies with a Zeitwerk NameError naming a constant the user never wrote, and in development the modules are silently missing. - **A10**: `Util.resolve` is `File.expand_path`, which doesn't resolve symlinks; Zeitwerk walks real directories, so a symlinked output (or an absolute path through a symlinked ancestor — the Capistrano `current/` shape) is neither ignored nor caught by `check_generated_ignored!`'s `start_with?` check against real roots. `File.realpath` when the path exists. Spec + app boot (`GW_PROBE=symlink`), and the `to_prepare` case must now produce the intended refusal.
- **C7**: an output under `config.autoload_once_paths` gets advice that can't work — the `once` autoloader is set up in bootstrap, before `load_config_initializers`. Detect it and say what does work.
- **C8**: `check_generated_ignored!` consults only graph_weaver's own `ignored_dirs`, so an app that already called `Rails.autoloaders.main.ignore(dir)` is refused with a false claim. Ask Zeitwerk (`ignores?`) before refusing.
