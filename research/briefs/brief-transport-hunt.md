# Lane: transport hunt

Read /tmp/claude/graph_weaver/brief-common.md for toolchain, gate, trailers. Baseline: main **4fd16d2** (you are in a worktree off it). CHANGELOG lane marker `<!-- lane: transport2 -->` as a new block under `###  Unreleased`. Every gate command its own Bash call.

You are the skeptic who has run GraphQL clients in production behind bad proxies. The transport layer (`lib/graph_weaver/transport/http.rb`, `transport/faraday.rb`, `retry.rb`, the `Client` url branch, and the `ServerError`/`TransportError` arms in `errors.rb`) has had far less adversarial attention this release than codegen or the test harness. Hunt it the way the earlier hunts did (`/tmp/claude/graph_weaver/hunt3-report.md` shows the shape: numbered findings, severity, a runnable repro per finding, then fixes): first a report, then fix what you own with a spec that fails before the fix.

Cases to drive, with a real local server (WEBrick or Rack in-process, `spec/integration/router_parity_spec.rb` shows the bootstrap pattern) rather than WebMock wherever the behavior is about bytes on the wire:
- Bodies: malformed JSON, empty body with 200, JSON that isn't an object (array, string, null), `data` that is a string, a BOM, gzip and deflate `Content-Encoding` (does the bundled transport ask for it, and decode it?), chunked transfer, a body larger than a few MB, non-UTF-8 bytes, `Content-Type: text/html` with a 200 (a captive portal or a proxy login page).
- Statuses: 4xx/5xx with an HTML body, 401 with a `WWW-Authenticate`, 429 with `Retry-After` (seconds and HTTP-date, does `Retry` honor it?), 3xx redirects (followed? to another host? does the Authorization header leak across hosts?), 204, 100-continue.
- Timing: open timeout vs read timeout on a server that accepts and never writes; a server that writes headers then stalls; a keep-alive connection the server closes between requests (does the pool retry a stale socket, and does it retry a *mutation* on a stale socket, which is the one case it must not?); fork after a connection is open (Puma preload, already validated once, don't redo unless you find a new angle).
- Headers: proc headers raising; a header value with a newline; a proxy from `http_proxy`/`HTTPS_PROXY` env (honored? by both transports?); `Accept`/`Content-Type` sent; a custom `User-Agent` and the default one naming the gem version.
- Retry: `retry_on` and `retry_codes` interaction with a `ServerError` that carries a body; backoff arithmetic at the boundaries (`max_delay`, jitter of 0 and 1); a retry that succeeds after a partial-error response; `retry_mutations` default; what `Failure.timeout` in the test harness produces versus what the real transport produces for the same case (they should raise the same class with the same shape).
- Faraday parity: every case above that has an answer on the bundled transport gets the same answer on Faraday, or the difference is documented.
- Errors: every `TransportError`/`ServerError` names the url with the query string and userinfo redacted, carries `headers` case-insensitively, and never includes a request body or variables (redaction is a contract, see `internal/redact.rb`).

Ownership: `lib/graph_weaver/transport/**`, `lib/graph_weaver/retry.rb`, `lib/graph_weaver/client.rb`, `lib/graph_weaver/errors.rb` (the transport/server arms only), `lib/graph_weaver/internal/redact.rb`, `lib/graph_weaver/testing/failure.rb` only if a harness/transport shape mismatch needs it, `spec/transport*_spec.rb`, `spec/retry_spec.rb`, `spec/client_spec.rb`, `spec/errors_spec.rb`, new specs, `docs/transport.md` or wherever the transport is documented (find it), `docs/errors.md` (transport arms only), `CHANGELOG.md` (your block), `spec/support/public_surface.txt` via `bin/public-surface --update`.
