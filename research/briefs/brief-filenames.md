**The bug.** A module's name comes from its file name, and `Internal.generated_names` strips only the last extension while `Inflect.camelize` splits only on `_`, so `hello.query.graphql` → `"Hello.queryQuery"` and `get-hello.graphql` → `"Get-helloQuery"`, both refused as not a constant name. 100% of GitLab's query corpus and every kebab-case shop hit it on the first file. The design principle "match the ecosystem's conventions" applies: GitLab, Apollo and Relay tooling all name files this way.

**Decide the rule so it fits in one sentence, then implement it.** Candidates: (a) every non-alphanumeric run in the base name is a word boundary (`get-hello` → `GetHello`, `user.profile` → `UserProfile`) — but then `hello.query.graphql` → `HelloQueryQuery`, a doubled suffix; (b) additionally, a trailing kind suffix that names the operation's own kind (`.query`, `.mutation`, `.subscription`, `.fragment`) is dropped before camelizing, because the module name already carries the kind — `hello.query.graphql` → `HelloQuery`, and a file whose kind suffix disagrees with its operation (`hello.query.graphql` holding a mutation) is refused naming both. (b) is a rule with a four-word list, but the list is GraphQL's own operation kinds, not ours. Check what the existing suffix rule does today (`Query`/`Mutation` appended from the operation kind) and keep one source of truth. Collisions that the widened rule creates (`foo.graphql` and `foo.query.graphql` → the same module) go through the existing collision refusal. Stripping *all* extensions is wrong (`user.profile.graphql` would lose `profile`); say so in the commit.
