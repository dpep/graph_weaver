You are the staff engineer who owns generation. The standard: generated code looks authoritative, so a silent wrong output is the most expensive thing this library can produce, and `verify` reporting success on a broken module is the safety net lying. Findings, in the order to take them:

- **B0**: `Codegen#declare_operation_name` splices the module name at a byte offset from graphql-ruby's `operation.col`, which is wrong for a one-line anonymous body preceded by a comment; the result is a `QUERY` that doesn't parse, and `generate!` and `verify` both report success. Two fixes, do both: find the operation start without trusting `col` (scan for the first non-ignored token, or splice at the token the parser hands you), AND re-parse the spliced document so a bad splice refuses at generation naming the file — the second is the safety net that must never lie again. Spec: the exact table in the hunt report (anonymous+comment one-line, anonymous `query`+comment, named+comment, multiline, blank line, leading spaces) all generate a document that parses and declares the name.
- **A6b**: `Emit#emit_module` `.rstrip`s every query line, editing block-string values. Strip only the line's own newline, keep the delimiter-collision guard. Spec: a `"""…"""` argument with trailing spaces and a spaces-only line survives byte-for-byte into `QUERY`.
- **A4**: `GraphBuilder` snapshots `Codegen.registry` at declaration, so a top-level `register_scalar` after a graph declaration never reaches it — while the v0.7.0 CHANGELOG promises the opposite. Decide: lazy resolution (top-level registry plus the block's overlay, read at generation) or refuse a top-level registration made after any graph is declared. The lazy path keeps the changelog's promise and matches how `schema: -> {}` already resolves late; pick it unless it breaks the "block runs where written" rule (registrations inside the block still run at declaration — only the *top-level* layer is read late). Spec: order-independent. Fix the `untyped_scalars` advisory too if it still fires wrongly.
