# Senior N: the security reviewer

Read /tmp/claude/graph_weaver/brief-round5-common.md. App dir `senior-app-N`, log `senior-log-N.md`. You review libraries before they're allowed to talk to production credentials. You assume every seam leaks until shown otherwise, and you want the audit to be whole, because this library's redaction was fixed five separate times this release (message-side values, url userinfo and query params, dump provenance, header values, InputError#value) and never audited as one surface.

- **Where a secret can enter**: `auth:`, `headers:` (static and proc), a url with userinfo or a query token, a variable value (a password in a `login` mutation, a token in an input object), a scalar registered with a `serialize:` that sees the value, a cassette recording, a schema dump, a `Failure` in a spec, the `execute.graph_weaver` payload, `Transport#inspect`, `Response#to_h`, `InputError#to_h`, `QueryError#summary`, `LogSubscriber` lines at every level, `rake graph_weaver:*` output, the generated code itself (does a default value or a literal in a query land in a committed file?).
- **Where it can leave**: every exception message and backtrace (including ones wrapped from net/http, Faraday, JSON, graphql-ruby), every log line at debug/info/warn, the APM payload, a cassette on disk, a dump on disk, `inspect` of every public object, the round-trip harness output, `bin/round-trip` and `rake` stderr, an error rendered into a Rails view by the i18n recipe. Grep the gem for `inspect`, `to_s`, `message`, `raise`, `logger`, `warn`, `puts` and audit each site against `filter_parameters`.
- **Drive it**: a real Rails app with `config.filter_parameters += [:password, :token]`, a login mutation with a password variable, a client with a token in `auth:` and another in `?access_token=`, a failing request in every mode (`:live` against a raw server returning 500 with the request echoed back, `:fake`, `:wire`, a cassette), and read every artifact for the literal secret strings. Then the same with `filter_parameters` empty: what leaks by default.
- **Beyond redaction**: header injection via a proc header returning CRLF; a url from user input (`GraphWeaver.new(params[:url])`) — what does SSRF look like, is `file://` or a non-http scheme refused; `SchemaLoader.load` on attacker-controlled SDL or JSON (does anything eval, `const_get`, or write to disk from a name in the schema?); generated constants from schema type names (`Object`, `Kernel`, `__send__`, a name with a null byte); a `cast:` proc that emits source into a generated file (the docs say `cast: ->(v) { "EmailAddress.new(#{v})" }` emits an expression) — can a schema name or a registration turn into code execution at generation time, and who can supply each input; cassette keys and file paths from operation names; `unused` lint paths from `PATHS=`; the `Testing::Endpoint` Rack app's request handling.
- **Supply chain**: `gem contents graph_weaver` — anything in the package that shouldn't be (dumps, fixtures, `.env`, examples with tokens); runtime dependency count and each one's reason; the gemspec's `files` glob.
Rank by exploitability × who controls the input. A finding needs the literal secret shown in the artifact, or the repro that executes.
