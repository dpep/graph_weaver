# Lane: transport, coercion, scalars — A1, A6, A7, B1, B2, B3, C7, plus two hunches to decide

Read /tmp/claude/graph_weaver/brief-hunt-common.md first.

You are the production engineer who owns the wire. The standard: a client library must not lie to a caller about which response is theirs, and every failure a transport can produce must arrive as a `GraphWeaver::Error` a caller can rescue. Findings, in the order to take them:

- **A1**: `Transport::HTTP`'s pool is not fork-safe — a socket warmed before `fork` (Puma `preload_app!` plus an initializer that introspects) is shared by every worker and callers receive each other's responses, no error. Record `Process.pid` on the pool; when it differs at lease time, abandon `@idle` without `finish`ing (closing would kill the parent's fd). Spec: the hunt's `probe3_fork.rb` shape as a spec that forks (guard with `Process.respond_to?(:fork)`), children see `crossed: 0`. Then check `Client#schema`'s memo and anything else pooled or memoized per process for the same shape.
- **B1**: `Net::HTTPBadResponse`, `Net::ProtocolError`, `Zlib::Error` escape unwrapped and `Retry` won't retry them; the Faraday transport wraps the same failures. Wrap them in `TransportError`; decide per class whether it's retriable and say so in the spec.
- **B2**: `Transport::Faraday#url` drops the query string (Faraday moves it into `params`), so `:wire` stubs the wrong endpoint and the boot log line lies. Reconstruct from `url_prefix` + `params`, or keep the caller's string. Spec over the hunt's url table.
- **B3**: debug logging `JSON.generate`s variables before the guarded encode, so a listener at debug changes the exception class (and in `InProcess`, the behavior). Encode once, log the encoded body; same for `in_process.rb`. Note `Internal::RequestKey.normalize_variables` may have the same shape — it's the harness lane's file; report the exact change if one is needed.
- **A6**: `Time`/`DateTime` serialize as `iso8601` with no precision, so sub-second timestamps from a JS/Apollo server round-trip lossy. Emit `iso8601(v.subsec.zero? ? 0 : 6)` (or the fractional digits the value carries — pick one rule), and make `Internal::Values` fabricate a fractional timestamp sometimes so `bin/round-trip` can see the class of bug. Update the `docs/scalars.md` wire table.
- **A7**: `Coerce.float("1e400")` is `Infinity` silently; refuse a non-finite parse like `whole` does for `Int`.
- **C7**: a `Time` given for a `Date` variable (and `Date` for `Time`, and a `TimeWithZone`-alike) surfaces Ruby's raw "no implicit conversion". The 0.7.0 rule is "a date stays a Date, a timestamp a Time": so refuse cross-type with `expected a Date, got a Time` naming the variable — do NOT silently convert (a Time→Date drops the time; a Date→Time invents midnight). Accept a `TimeWithZone`-alike where a `Time` goes (`respond_to?(:to_time)` and `acts_like?(:time)`), since that is the everyday Rails value and is lossless.
- **Two hunches to decide, not necessarily build**: `Int` is never range-checked (`2**200` goes out as a JSON number), and `BigDecimal#to_s("F")` expands `1e400` to 400 digits. State the rule you'd ship in one sentence each; implement only if it's a refusal that can't be wrong (32-bit `Int` range is spec: refuse outside it, naming the variable and suggesting `BigInt`).
