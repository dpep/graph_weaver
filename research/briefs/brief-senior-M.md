# Senior M: the skeptic migrating a scalar-heavy app from graphql-client

Read /tmp/claude/graph_weaver/brief-senior4-common.md. App dir `senior-app-M`, log `senior-log-M.md`. You maintain a Rails app on `graphql-client` with fifteen hand-handled custom scalars and you are evaluating a switch; you name the load-bearing assumptions, steelman the docs, and run the cheap test before believing anything.

- **The scalar zoo, registered at scale.** An in-process schema with fifteen custom scalars of the kinds real apps have: `Upload`, `JSON`, `Cursor`, `Base64`, `GeoJSON`, `Timezone`, `Locale`, `Color`, `Email`, `PhoneNumber`, `Percentage`, a prefixed global id (`gid://app/User/1`), `CurrencyCode`, `Bytes`, `UUID`. Register every one per docs/scalars.md, in one initializer. How long does it take, how many lines, how many needed a `cast:`/`serialize:` pair vs a class alone, what did the advisory say about the ones you skipped, and does `srb tc` over the generated output stay clean. Then miss three on purpose and see what generation, `verify`, and runtime each say.
- **Upload / multipart.** A mutation taking `Upload!`: what the client does (the GraphQL multipart request spec, or nothing); if nothing, what a team has to write and whether the transport's seam lets them.
- **Scalars in the corners.** A scalar field on a union member and on an interface field selected through fragments; a list of lists of a scalar (`[[Decimal!]!]`); a scalar argument with a schema default value that the query doesn't pass; a scalar variable used in `@skip(if:)`; a scalar inside a `@oneOf` input; a nullable scalar list with null elements; the same scalar name registered globally and inside a graph block (which wins).
- **The migration itself.** Take three real graphql-client call sites (a query with `GraphQL::Client::HTTP`, a fragment-heavy one, a mutation with an input object) and port each; count what changed, what the generated code lets you delete, and what you lost (graphql-client's `#to_h` shapes, its fragment-as-module pattern, its `Client.parse` at load time). Write the alternatives.md row from your side and check it against the one docs/alternatives.md has.
- **Steelman then test.** Pick the three strongest claims in README/docs/scalars.md and try to falsify each with a five-minute experiment.
