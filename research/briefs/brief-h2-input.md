# Lane: input errors — A1, A2, B1, C1, C2, C3, C4, C5, the D paper cuts on InputError, and the input-side hostile harness

Read /tmp/claude/graph_weaver/brief-hunt2-common.md first.

You are the platform expert who shipped `InputError`'s kinds/path/coordinate and now owns its edges. Two of these are secret leaks and go first.

- **A1**: a typo'd filtered key (`passwrod`) misses the `password` filter, so `#value`/`to_h` carry the secret while `details[:suggestion]` names the key the filter would have matched. The report offers two fixes; take the one-rule one: an unknown-key error attaches no `value:` at all — the key is the problem and the value has no slot. Spec: `to_h` has no `"value"` and the secret appears nowhere (message, value, warn line).
- **A2**: `ServerInput.build` redacts `value:` but not the message graphql-ruby wrote, which quotes the rejected value. Apply the same `Redact.detail(path.last, message)` the client side uses, for all three server shapes. Spec in `spec/filtered_messages_spec.rb` per shape.
- **B1**: `InputError#to_h` isn't JSON-serializable when `value` is `NaN`/`Infinity`, so the documented `render json: e.to_h` 500s inside the error handler. `value` must be JSON-clean: for a non-finite Float carry its `to_s` (or the original argument). Spec: `JSON.generate(e.to_h)` for both refusals. Also the `extensions.input.value` route (probe4 case 4).
- **C1 + C2**: `InputStruct.element` only rescues `InputError`, but leaf coercers raise branded plain errors, so every list of leaves loses its index and `path` is `["ids"]` not `["ids", 2]`; a list-of-lists with a nil/non-list element surfaces a raw `NoMethodError`. Give `element` the `rescue StandardError` branch `field` has (build the InputError with `path: [index]`, `value: element`, `kind: Refusal.kind_of(e)`), and type-check before the inner `.map`. The one spec covering indices used a list of input objects — add lists of Int, enum, String, and `[[Int]]` with a nil element. Verify no fixture regeneration is needed (one emit site, one runtime method); if it is, regenerate.
- **C3**: `ServerInput.explained`'s NOT_DEFINED branch builds `coordinate` from `path.last`, which is the variable name when the problem's own path is empty → `CredsIn.creds`, a slot that doesn't exist. Use the problem's own path; nil when empty.
- **C4**: a `@oneOf` input with exactly one field explicitly null is told to "supply exactly one field". Say the field was null; give it `kind: :missing`, `path: [that field]`.
- **C5**: `Hints#respond_to_missing?` answers true for near-miss names, so `obj.pet if obj.respond_to?(:pet)` raises. Keep the `method_missing` hint; let `respond_to_missing?` fall through to `super`.
- **D paper cuts**: `details` values from a server are type-unchecked (`members: "not a list"` gets through — `DETAILS` closes keys, close types too, drop what doesn't fit); a wrong-typed list element loses its value (C1 covers it — confirm); `to_h`'s `.compact` conflates null-value with no-value (decide: keep `nil` when the producer said null — or leave with a reason); `#field` returns a stringified index for a list-element failure (decide what `field` should be there; document).
- **The harness's blind spot**: `bin/round-trip --hostile` spoils response leaves only; nothing feeds a bad input value and checks the `InputError` describes it. Add an input-side hostile mode to `spec/support/round_trip.rb` and `bin/round-trip`: for a drafted input, corrupt one leaf (wrong type, unparseable string, non-member enum, nil in a non-null list slot, a Hash where a scalar goes) at a random depth including inside lists, run the generated `execute` against a spy client, and assert an `InputError` whose `path` points at the corrupted slot and whose `kind` matches the corruption. Run it at `-c 2000` on the fixtures and on `examples/github/schema.json`; anything it finds is a finding for your report (fix it if it's in your files). Also the round-trip prophylactic: teach the drafter not to alias different leaf types onto one response key across union members (hunt 2's `legacy_invalid` isolation) — same file.
