  - **"A subgraph times out while another answers" has literally no representation in this testing model, under either `:router` or `:wire`.** Under `:router`, `@subgraphs.fetch(name).execute(...)` is an in-process Ruby method call on a schema class -- there is no transport, so nothing can time out. Under `:wire`, the WHOLE federated graph sits behind exactly ONE stubbed url (the gateway's own endpoint) -- `Failure.timeout`/`stub_request(...).to_timeout` can only fail the entire stitched request as a unit, never one subgraph's hop specifically while its siblings still answer, because the per-subgraph HTTP calls a real gateway makes never leave this process to begin with. This is an honest, load-bearing consequence of "faithful subset, not a gateway" (docs/federation.md) rather than a bug, but it means a team wanting "one subgraph degrades gracefully while others still answer" as a tested behavior cannot get it from this library at all -- that scenario needs a real gateway (or the `router_parity_spec.rb`-style external harness) to exercise honestly.
